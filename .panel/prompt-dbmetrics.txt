## Question under review

Business Central (Microsoft Dynamics 365 BC, on-prem BC28 / 2026 wave 1 and SaaS). A tool (al-perf) analyzes BC CPU profiles + telemetry to find performance problems, and wants to attach REAL database-operation metrics (SQL statements, counts, rows read, durations, locks/waits) to its findings.

I have built an inventory of every source of BC **database-operation metrics** I could find, verified against the decompiled BC28 AL source (`BC.history`) and real captures. My claims:

1. **In-app Performance Profiler = SAMPLING ONLY.** The AL API (`System.Tooling`, `dotnet.al`) wraps `Microsoft.Dynamics.Nav.Runtime.Debugger.SamplingProfiler` producing a **V8 CpuProfile** (`.alcpuprofile`). There is NO instrumentation profiler in the AL API, and no SQL on/off toggle. SQL statements appear as profile call-tree nodes (the node's `Method Name` / V8 `functionName` IS the SQL text). Cost is a **sampled estimate** (`Hit Count` x sampling interval), NOT a per-statement measured duration. `Self Time` is exclusive of children; SQL nodes are children of the AL frame that issued them.
2. **Instrumentation profile (`.mdc` flatbuffer snapshot) carries NO SQL.** Proven on a real BC28 capture: 15,674 `.mdc` files, zero with DB-SQL markers (`dbo."`, `READUNCOMMITTED`, `FROM dbo.`); the payload is AL execution detail (methods, variables, values, exact counts). This is why the ir-json interchange (converted from `.mdc`) has `Invocation.sql` always empty.
3. **BCPT / Performance Toolkit** (`BCPTLogEntry` table) = a MEASURED per-operation metric: field "No. of SQL Statements" (Integer) + "Duration (ms)" (SIFT-indexed). Count + real duration, but NOT the statement text and NOT rows-read. In-app, SaaS + OnPrem. Requires running a benchmark suite.
4. **Table Information** (System App) = per-table row counts / size.
5. **RT0005 long-running-SQL telemetry** (Application Insights) = per slow statement: `sqlStatement` + `executionTime` + `alStackTrace`. Report telemetry adds `sqlExecutes` / `sqlRowsRead`. This is the ONLY place statement + rows-read + duration exist together. SaaS + OnPrem.
6. **Per-statement SQL text WITH rows-read is NOT AL-accessible** — AL exposes only the profiler's `Method Name` SQL (estimated cost) and BCPT's count; the full statement+rows+duration lives only in platform telemetry (RT0005).
